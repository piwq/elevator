# Проект симулятора

Дизайн вытекает из [RESEARCH.md](RESEARCH.md): моделируем то, что моделируют
валидированные индустриальные симуляторы (Elevate, KONE BTS), и верифицируем
по классической аналитике (Barney RTT).

## 1. Архитектурные решения

### Событийная симуляция с аналитической кинематикой

Elevate использует time-slice (шаг 0,01 с). Мы выбираем **discrete-event**
ядро: формулы режимов A/B/C дают *точное* время любой поездки в замкнутой
форме, поэтому интегрировать движение по шагам не нужно — событийная модель
быстрее и без ошибки дискретизации. Позиция/скорость кабины в произвольный
момент восстанавливается аналитически из текущего профиля (для анимации и для
решения «можно ли ещё остановиться на этаже X» — критерий: этаж X дальше
тормозного пути v²/(2a)+... текущего профиля).

События: прибытие группы пассажиров, завершение фазы движения, окончание
открытия/закрытия дверей, истечение dwell, завершение посадки/высадки.

### Модули

```
sim/
  kinematics.py    # S-кривая: режимы A/B/C, время поездки, позиция(t), тормозной путь
  building.py      # этажи, высоты, население по этажам (из квартир/спален)
  passengers.py    # генератор: неоднородный Пуассон групп + геометрический размер группы
  traffic.py       # суточный профиль жилого дома (доли in/out/interfloor по времени)
  car.py           # состояние кабины: позиция, направление, загрузка, двери, приказы
  controller.py    # интерфейс диспетчера + FullSelectiveCollective (базовый)
  engine.py        # событийное ядро (heapq), часы, журнал событий
  metrics.py       # AWT, transit, TTD, перцентили, очереди, загрузка, % за 5 мин
  experiment.py    # реплики с разными seed, warm-up, доверительные интервалы
```

Интерфейс `Controller` — точка расширения: позже добавляются Nearest Car / ETA
для группы лифтов и RL-диспетчер, сравнение на одинаковом потоке пассажиров
(common random numbers).

### Модель пассажира

Жизненный цикл: `created → waiting → boarding → riding → alighting → done`,
с метками времени на каждом переходе — из них считаются все метрики. Пассажир
имеет этаж происхождения/назначения и принадлежность к группе (batch).
Отказ от посадки в полную кабину — пассажир остаётся в очереди, вызов
перерегистрируется.

### Генерация спроса

Неоднородный Пуассоновский процесс прибытия **групп** (thinning-алгоритм по
кусочно-постоянной интенсивности λ(t) из суточного профиля), размер группы —
геометрическое распределение со средним 1,2 (жилое: 1,1–1,4). Доли
входящего/исходящего/межэтажного трафика зависят от часа; происхождение и
назначение разыгрываются по населению этажей (вход/выход — через 1-й этаж).

## 2. Параметры по умолчанию (с обоснованием)

Базовый сценарий: 17-этажный жилой дом, 1 подъезд, 1 лифт.

| Параметр | Значение | Обоснование (см. RESEARCH.md) |
|---|---|---|
| Этажей | 17 (16 жилых + холл) | типовая жилая башня |
| Высота этажа | 3,0 м | жилой стандарт 2,8–3,0 м |
| Квартир на этаже / чел. на квартиру | 4 / 2,7 | CIBSE: 1,5–1,9 чел/спальню, средняя 1–2-спальная |
| Номинальная скорость v | 1,6 м/с | 6–12+ этажей → 1,0–1,75 м/с; v ≈ H/20 = 48/20 ≈ 2,4 → берём ближайший стандартный ряд вниз для жилого |
| Ускорение a | 1,0 м/с² | каноничная пара литературы |
| Рывок j | 1,0 м/с³ | каноничная пара литературы |
| Открытие дверей | 2,0 с | CIBSE, центральное открывание |
| Закрытие дверей | 3,0 с | CIBSE / TSSA 2,9–4,0 с |
| Dwell (вызов / приказ) | 4,0 / 2,0 с | патенты Otis, ADA ≥ 3 с по вызову |
| Время входа/выхода tp | 1,2 с/чел | Barney/CIBSE; чувствительность проверить с 1,75 с (ISO 4190-6 residential) |
| Кабина | 630 кг / 8 чел | стандартный ряд EN 81-20 |
| Эффективная вместимость | 80% → 6 чел | конвенция CIBSE |
| Пиковый спрос | 6% населения / 5 мин | ISO 8100-32 residential |
| Средний размер группы | 1,2 (геометрическое) | Sorsa et al. 2021 |
| Поездок на жителя в день | ~4 | энергетическая литература (низкая уверенность — параметр калибровки) |

Суточный профиль (кусочно-постоянный, доли от пикового λ; форма по Siikonen —
утренний down-peak, вечерний пик с преобладанием входящего, двусторонний день;
точные часы — наша параметризация, подлежит калибровке):

| Часы | Интенсивность | Микс in/out/interfloor |
|---|---|---|
| 00–06 | 0,05 | 50/50/0 |
| 06–09 | 1,0 (утренний пик) | 15/75/10 |
| 09–16 | 0,35 | 40/40/20 |
| 16–20 | 0,9 (вечерний пик) | 55/30/15 |
| 20–24 | 0,4 | 45/45/10 |

## 3. Метрики и критерии приёмки сценария

Выход прогона: AWT, медиана и 90-й перцентиль ожидания, среднее TTD, transit,
макс. длина очереди по этажам, средняя/пиковая загрузка кабины, фактический
интервал, обслужено чел./5 мин. Критерии качества: AWT ≤ 40 с (ISO two-way
residential), интервал ≤ 60 с, ожидание ≤ 90 с для 90-го перцентиля.

## 4. План верификации и валидации

1. **Кинематика**: время поездки из событийного ядра == формулы A/B/C; границы
   режимов непрерывны (unit-тесты).
2. **Генератор**: K–S тест экспоненциальности межгрупповых интервалов; средний
   размер группы; фактический % населения/5 мин == заданному.
3. **Up-peak эталон**: симуляция чистого up-peak (100% входящий) должна
   воспроизводить RTT Barney (2H·tv + (S+1)·ts + 2P·tp с E[S], E[H]) с точностью
   до стат. погрешности — главный верификационный тест.
4. **Насыщение**: ступенчатое повышение спроса → очереди должны расходиться
   вблизи аналитического UPPHC.
5. **Валидация правдоподобия**: суточный прогон — пиковая интенсивность и микс
   сопоставимы с измерениями Siikonen (≤ 5,7%/5 мин, ~40/40/20).
6. **Методология**: каждый сценарий ≥ 120 мин модельного времени, warm-up 15 мин
   отброшен, ≥ 10 реплик, отчёт с 95% доверительными интервалами.

## 5. Этапы реализации

1. Ядро: kinematics + engine + car + full selective collective, детерминированный
   поток — проходят верификационные тесты 1–3.
2. Стохастический спрос + суточный профиль + метрики + experiment runner (4–6).
3. Отчёты/визуализация: график положения кабины (trajectory diagram), тепловая
   карта ожиданий по этажам/часам, распределения AWT.
4. Расширения: 2+ лифта (Nearest Car/ETA), сравнение диспетчеров, RL-песочница.
